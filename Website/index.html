How it works

  1. 01

    Run

    Install Capsi on each Windows computer, open it, and give the device a name.

  2. 02

    Find

    Capsi announces each device over a supported local communication network, so nearby devices running Capsi can show up without typing addresses.

  3. 03

    Send

    Accept a device once, then send messages and files directly between those devices.

Features

Small scope, on purpose. Each item below is a different part of how Capsi works.

Device Discovery

Devices running Capsi announce themselves over a supported local communication network and appear in the Nearby list.

Direct Messages

One-to-one text messages between accepted devices, kept in a per-device conversation.

File Transfer

Offer a file to an accepted device; the other side accepts or declines, then receives it. One file per offer, up to 100 MB.

Accept-Once Trust

New devices appear as pending. Messages and files only flow after you accept a device; ignored devices stay blocked.

No Cloud Service

Local communication does not go through a Capsi chat server — devices talk directly over their available communication path.

No Account

No signup or login. A device name (up to 32 characters) is the identity other computers see.

Your network. Your devices. Your data.

Capsi is designed for places where devices can reach each other over an available local communication network — LAN, Wi-Fi, mobile hotspot, and other supported network interfaces — without a chat service in the middle.

No external chat server is required for basic device-to-device communication. Downloads and release metadata still come from GitHub; your messages and files do not pass through a Capsi cloud.

Local networking is not the same as encryption or invisibility: anyone else sharing the communication network can observe traffic patterns, and a network owner can inspect or block local traffic.
